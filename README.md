# Віртуальна Екзаменаційна Комісія на базі Hermes Agent 🎓

Система для імітації роботи екзаменаційної комісії при захисті дипломних та курсових робіт студентів. Побудована на платформі [Hermes Agent](https://github.com/nousresearch/hermes-agent) з інтеграцією через Telegram.

**Призначення:** науково-педагогічний експеримент з моделювання адаптивної поведінки віртуальної комісії.

## 📋 Як це працює

1. Студент надсилає PDF-файл роботи у Telegram-бот.
2. Три віртуальні експерти по черзі аналізують роботу та задають питання:
   - 📚 **Академічний експерт** — структура, бібліографія, логічна зв'язність
   - 🔬 **Експерт-практик** — емпіричні дані, особистий внесок, практична цінність
   - 🚀 **Експерт-візіонер** — реальне застосування, масштабованість, стрес-тест висновків
3. Модератор збирає оцінки та формує підсумкове резюме (0–100% за 4 критеріями).

Мова спілкування — **українська** (формальний академічний стиль).

## 📋 Системні вимоги та підготовка

Перед запуском скрипта переконайтеся, що у вас є:
1. **Акаунт Google Cloud Platform** з прив'язаною платіжною карткою.
2. **API-ключ Gemini** (отримайте на [Google AI Studio](https://aistudio.google.com/)).
3. **Токен Telegram-бота** (створіть через `@BotFather`).

## ⚡ Інструкція із запуску

1. Увійдіть у **[GCP Console](https://console.cloud.google.com/)**.
2. У правому верхньому кутку натисніть іконку **Activate Cloud Shell** (>_), щоб відкрити термінал у браузері.
3. Зробіть клон репозиторію з проєктом:
   ```bash
   git clone https://github.com/dmtesttask/AI_Hermes.git HermesCommission
   ```
4. Перейдіть до каталогу:
   ```bash
   cd HermesCommission
   ```
5. Зробіть скрипт виконуваним та запустіть його:
   ```bash
   chmod +x setup-gcp.sh
   ./setup-gcp.sh
   ```

---

## ⚙️ Що робить скрипт?

1. **Вмикає API**: Активує служби Compute Engine та Secret Manager у вашому проєкті GCP.
2. **Налаштовує Secret Manager**: Безпечно зберігає API-ключ Gemini та токен Telegram-бота (запитуються в консолі при запуску). Ключі ніколи не потраплять у вихідний код!
3. **Створює права доступу**: Налаштовує спеціальний сервісний акаунт ВМ (`hermes-vm-sa`) із мінімальними правами (доступ лише до цих двох секретів).
4. **Створює ВМ**: Запускає віртуальну машину (e2-medium, us-central1-a, Ubuntu 24.04, 30 GB HDD).
5. **Ініціалізує сервер (ВМ)**:
   - Оновлює пакети, встановлює Node.js 22 LTS та Git.
   - Встановлює Hermes Agent CLI.
   - Створює ізольованого системного користувача `hermes` для запуску сервісу.
   - Отримує ключі зі Secret Manager та налаштовує Hermes Agent:
     - Модель: Gemini 3.1 Flash Lite (основна)
     - Вимкнення зайвих інструментів (terminal, file, web, code) для безпеки
     - Налаштування delegation (послідовна робота критиків)
   - Прописує автозапуск через `systemd` сервіс `hermes-gateway`.
   - Встановлює глобальний аліас `hermes` для зручності.
6. **Завантажує агентів**: Клонує конфігураційні файли з репозиторію на ВМ:
   - `SOUL.md` → `/home/hermes/.hermes/SOUL.md` (особистість модератора)
   - `AGENTS.md` → `/home/hermes/workspace/AGENTS.md` (оркестрація комісії)

## 🔗 Підключення до Telegram (Pairing)

Після успішного виконання скрипта:
1. Знайдіть вашого бота в Telegram та надішліть йому будь-яке повідомлення (наприклад, `Привіт`).
2. Бот відповість вам повідомленням з **кодом** (Pairing Code).
3. Підключіться до віртуальної машини через Cloud Shell:
   ```bash
   gcloud compute ssh hermes-commission --zone=us-central1-a
   ```
4. Активуйте з'єднання бота (введіть код з кроку 2):
   ```bash
   hermes pairing approve telegram <ВАШ_КОД>
   ```

## 👥 Налаштування ролей та оркестрації

Hermes Agent використовує два головні конфігураційні файли:

### 1. `SOUL.md` — Особистість модератора
Визначає хто такий головний агент: його роль, стиль спілкування, процедуру захисту.
- Розташування на ВМ: `/home/hermes/.hermes/SOUL.md`
- Мова файлу: англійська (для точності), але агент спілкується українською

### 2. `AGENTS.md` — Оркестрація комісії
Описує трьох критиків, їхні компетенції, сценарій виклику через `delegate_task`, формат підсумків.
- Розташування на ВМ: `/home/hermes/workspace/AGENTS.md`

### 3. Як додати або змінити роль
1. Підключіться до ВМ: `gcloud compute ssh hermes-commission --zone=us-central1-a`
2. Відредагуйте файли:
   - Оркестрація: `sudo -u hermes nano /home/hermes/workspace/AGENTS.md`
   - Особистість: `sudo -u hermes nano /home/hermes/.hermes/SOUL.md`
3. Перезапустіть сервіс: `sudo systemctl restart hermes-gateway`

## 🔄 Багатокористувацький режим

За замовчуванням система налаштована на роботу з одним користувачем з підтвердженням через pairing code.

**Варіант 1: Додати кількох студентів через pairing** (рекомендовано)

Кожен студент надсилає повідомлення боту → отримує Pairing Code → викладач його підтверджує:
```bash
# Підключіться до ВМ
gcloud compute ssh hermes-commission --zone=us-central1-a

# Підтвердити код студента
hermes pairing approve telegram <КОД_СТУДЕНТА>

# Переглянути список підключених
hermes pairing list
```

**Варіант 2: Відкрити доступ для конкретних студентів** (через allowlist)

```bash
# Підключіться до ВМ
gcloud compute ssh hermes-commission --zone=us-central1-a

# Додайте Telegram User ID студентів у .env
sudo -u hermes bash -c 'echo "TELEGRAM_ALLOWED_USERS=123456789,987654321" >> /home/hermes/.hermes/.env'

# Перезапустити сервіс
sudo systemctl restart hermes-gateway
```

> [!TIP]
> Дізнатися Telegram User ID: надішліть повідомлення `@userinfobot` або `@getmyid_bot`.

**Варіант 3: Відкрити доступ усім** (не рекомендовано)

```bash
# Додайте в config.yaml секцію gateway
sudo -u hermes nano /home/hermes/.hermes/config.yaml
```

Додайте в кінець файлу:
```yaml
gateway:
  platforms:
    telegram:
      extra:
        unauthorized_dm_behavior: "ignore"  # Не запитувати pairing code
```

Потім перезапустіть: `sudo systemctl restart hermes-gateway`

> [!WARNING]
> Відкритий доступ дозволяє будь-кому в Telegram взаємодіяти з вашим ботом, що може призвести до швидкого витрачання лімітів Gemini API (RPM = 15 для безкоштовного рівня).

## 🛠️ Управління та діагностика на сервері

Після підключення через SSH (`gcloud compute ssh hermes-commission --zone=us-central1-a`):

* **Перегляд логів Gateway** у реальному часі:
  ```bash
  journalctl -u hermes-gateway -f
  ```
* **Перезапуск служби**:
  ```bash
  sudo systemctl restart hermes-gateway
  ```
* **Діагностика системи**:
  ```bash
  hermes doctor
  ```
* **Перегляд конфігурації**:
  ```bash
  hermes config
  ```
* **Статус сервісу**:
  ```bash
  systemctl status hermes-gateway
  ```
* **Лог ініціалізації VM** (при першому запуску):
  ```bash
  cat /var/log/hermes-setup.log
  ```

## ⚠️ Обмеження API (Rate Limits)

Система використовує безкоштовний рівень Gemini 3.1 Flash Lite з обмеженням **RPM = 15** (15 запитів на хвилину).

- Одна захист споживає приблизно 12–15 запитів.
- Критики працюють послідовно для мінімізації навантаження.
- Якщо виникає помилка rate limit — зачекайте хвилину і повторіть.
